# Running the tests on a real nRF52840-DK

These tests normally run under QEMU (`nix flake check`, `nix run .#qemu-*`). The
nRF52840-DK target runs the **same binaries on real silicon** over the board's
on-board SEGGER J-Link, so the `src/cycles.h` DWT cycle counter returns real
numbers (QEMU's `mps2-an386` does not implement it).

The nRF52840 is the same CPU as QEMU's `mps2-an386` (ARM Cortex-M4F,
hard-float). Nothing in the test sources or `crt0_arm_v7m.S` changes — only the
memory map (`src/link_nrf52840.ld`: 1 MB flash @ 0x0, 256 KB SRAM @ 0x20000000)
and the runner (OpenOCD over SWD instead of QEMU). Semihosting is identical:
the `BKPT 0xAB` calls that QEMU intercepts are intercepted by OpenOCD.

## Prerequisites

- An **nRF52840-DK** connected by USB (the on-board J-Link enumerates as USB
  `1366:1015 SEGGER J-Link`; check with `lsusb`).
- The PolyBench submodule initialized (needed for any flake build):
  `git submodule update --init` from the repo root.
- USB access to the J-Link without root. The DK's J-Link is typically
  `root:plugdev`; add yourself to `plugdev` (`sudo usermod -aG plugdev $USER`,
  then re-login) if `openocd` reports a permissions error. Alternatively install
  udev rules: `openocd`'s `contrib/60-openocd.rules` into `/etc/udev/rules.d/`.

Everything else (OpenOCD, `arm-none-eabi-gcc`) comes from the dev shell.

## Quick start

```sh
# OpenOCD + the ARM toolchain are in the ARM Cortex-M4 dev shells:
nix develop .#arm-cortex-m4-gcc          # (or .#arm-cortex-m4-clang-libgcc)

# Flash + run one test; stdout is the program's semihosting output:
make run-nrf52840-00_semihosting-hello-world

# Compare against the expected output, exactly like the QEMU check path:
make run-nrf52840-01_constant | diff tests/01_constant/expected.txt -
```

`ARCH_FAMILY=arm` is exported by the ARM dev shells, so it's implicit above. The
target name is `run-nrf52840-<elf>`, where `<elf>` matches the QEMU `qemu-<elf>`
targets:

| test source                | elf / target suffix          |
|----------------------------|------------------------------|
| `tests/<t>/main.c`         | `<t>`                        |
| `tests/<t>/main_<sfx>.c`   | `<t>_<sfx>` (e.g. `05_box_wasm`) |

Other targets:

- `make flash-nrf52840-<elf>` — flash + reset-to-run, no semihosting capture.
- `make build-nrf52840-<elf>` — build the nRF52840 ELF only (into
  `build_nrf52840/`), don't flash.

## Run the whole suite

```sh
for t in tests/*/; do
  name=$(basename "$t")
  for exp in "$t"expected*.txt; do
    [ -e "$exp" ] || continue
    # main.c -> <name>; main_<sfx>.c -> <name>_<sfx>; expected_<sfx>.txt mirrors it
    sfx=$(basename "$exp" .txt); sfx=${sfx#expected}; sfx=${sfx#_}
    elf="$name${sfx:+_$sfx}"
    printf '%-32s ' "$elf"
    if make run-nrf52840-"$elf" 2>/dev/null | diff -q "$exp" - >/dev/null; then
      echo PASS
    else
      echo FAIL
    fi
  done
done
```

## Benchmarking (the reason for hardware)

`BENCH=1` enables the `src/cycles.h` timing in the `main_*.c` entrypoints. On
the nRF52840 `read_cycles()` reads `DWT->CYCCNT` (real cycles at 64 MHz);
`read_instret()` returns 0 (Cortex-M has no retired-instruction counter).

```sh
# Use a separate build dir so objects recompile with -DBENCH:
make BENCH=1 NRF52840_BUILD=build_nrf52840_bench run-nrf52840-06_polybench_atax_wasm
# -> [bench atax] cycles=2429249 instret=0
```

## Tunables

All overridable on the `make` command line:

| var                  | default                  | meaning |
|----------------------|--------------------------|---------|
| `NRF52840_HEAP`      | `131072`                 | bytes for the WASM linear-memory buffer (`-DWASM_RT_HEAP_SIZE`). Each WASM page is 64 KiB; lower it if a test's footprint won't fit 256 KB SRAM, raise it for memory-hungry modules. |
| `NRF52840_BUILD`     | `build_nrf52840`         | build directory for nRF52840 ELFs. |
| `NRF52840_LINK_SCRIPT` | `src/link_nrf52840.ld` | linker script (memory map). |
| `NRF52840_RUN`       | `./scripts/run-nrf52840.sh` | runner script. |

The runner (`scripts/run-nrf52840.sh`) also honors env vars `OPENOCD`,
`OPENOCD_INTERFACE`, `OPENOCD_TARGET`, `OPENOCD_TRANSPORT`, `NRF_TIMEOUT_MS`,
and `NRF_RETRIES` (OpenOCD attempts before giving up, default 5).

## How the runner works

`scripts/run-nrf52840.sh` drives OpenOCD standalone (no GDB):

```
init; halt; program <elf> verify; reset halt; arm semihosting enable; resume; wait_halt
```

OpenOCD services `SYS_WRITE` calls during polling (writing the bytes to **its
stdout**) and leaves the core halted on the program's `SYS_EXIT` call, so
`wait_halt` returns exactly when the program exits. OpenOCD's own log goes to
**stderr** (shown only on failure), keeping stdout clean for diffing.

## Troubleshooting

- **`Error: No J-Link device found`** — check `lsusb` and USB permissions
  (`plugdev` group / udev rules above).
- **`Registration failed: maximum number of connections on the device
  reached`** — the on-board J-Link caps concurrent connections and clears a
  stale one only a few seconds after the previous OpenOCD exits, so tight
  loops over the suite can hit this. The runner retries with progressive
  backoff (`NRF_RETRIES`), which clears it; raise `NRF_RETRIES` if a very long
  batch still trips it.
- **`wait_halt` timeout** — the program never called `exit()`; raise
  `NRF_TIMEOUT_MS` or check it isn't stuck in a `wasm_rt_trap` spin-loop.
- **Link error: region `SRAM` overflowed** — lower `NRF52840_HEAP`.
- **`openocd: command not found`** — you're not in the dev shell.
